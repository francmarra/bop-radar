# BoP Radar Car Comparator (React + TS) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local-only React + TypeScript single-page comparator in `web/` that consumes the bop-radar .NET API: pick 2–4 cars, choose set/version, see a side-by-side stats table (best value highlighted) and a PP-over-versions SVG chart.

**Architecture:** Vite SPA. `api/` layer = generated OpenAPI types + typed `fetch` client + TanStack Query hooks. URL query string is the state. Pure logic (`best.ts`, URL parsing) is unit-tested; components are tested with React Testing Library against MSW-mocked HTTP through the real client.

**Tech Stack:** Node 22, Vite, React 19, TypeScript (strict), TanStack Query 5, openapi-typescript, Vitest + jsdom + @testing-library/react + @testing-library/user-event, MSW 2, ESLint (typescript-eslint + react-hooks).

**Spec:** `docs/superpowers/specs/2026-10-22-react-compare-design.md`

## Global Constraints

- Everything new lives in `web/` plus `.github/workflows/web.yml`; `api/` changes only in `.github/workflows/api.yml` (Task 7). Never modify Python, `site/`, `data/`, `update.yml`, or any file under `api/src` / `api/tests`.
- Local only: no deploy, no mocks in production code. API base URL = `import.meta.env.VITE_API_URL ?? "http://localhost:8080"`; dev server port 5173 (CORS on the API already allows `http://localhost:5173`).
- TypeScript `strict: true`; `npm run lint`, `npm run typecheck`, `npm test -- --run`, `npm run build` must all pass with zero warnings/errors.
- API types come only from `web/src/api/schema.d.ts` generated by `npm run gen:api` (`openapi-typescript http://localhost:8080/openapi/v1.json -o src/api/schema.d.ts`); never hand-edit it.
- JSON from the API is camelCase (e.g. `psPerT`, `powerPs`, `torqueKgfm`, `weightKg`).
- URL state: `ids` comma-separated 0–4 unique (extra truncated to 4), `set` ∈ {h,m,l} default `m`, `version` optional (absent = "latest common"); invalid values fall back to defaults.
- Search: debounce 250 ms, min 2 chars, `GET /api/v1/cars?q=<text>&pageSize=10`.
- Best value: max is best for `pp`, `powerPs`, `torqueKgfm`, `psPerT`; min is best for `weightKg`, `rank`; no highlight for tier, balance, group; ties all highlighted; `null` shows "—" and is ignored.
- UI copy in English (exact strings): empty state `Pick 2 to 4 cars to compare`; max reached `Maximum 4 cars`; network error `Could not reach the API (<base URL>). Is \`docker compose up\` running in api/?`; retry button `Try again`; version option `Latest common`; best marker visually-hidden text `best`.
- Accessibility: combobox ARIA pattern (role=combobox/listbox/option, aria-activedescendant, ArrowUp/Down, Enter, Escape); table `<caption>` + `<th scope>`; chart `role="img"` + `aria-label`; loading region `aria-busy="true"`; focus visible; 44 px targets; table scrolls inside its own container on narrow screens.
- Theme: `web/src/theme.css` copies the `:root` variables (dark) and the light-theme overrides from `site/style.css` (light via `@media (prefers-color-scheme: light)`); fonts Barlow Condensed + JetBrains Mono via Google Fonts link in `index.html`.
- Commit messages end with a blank line then `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Branch `feat/react-compare`; never push.

## Review Focus

- Typing fast in the search box must send one request for the settled text and never show results of an older query → Task 4 test `debounces and only shows results for the latest text`.
- Picking a car that is already selected must not add a duplicate chip → Task 4 test `ignores a car that is already selected`.
- Opening a URL with 5+ ids, duplicates or `set=x` must normalize (first 4 unique, `set=m`) and rewrite the URL → Task 3 test `normalizes ids and set from the URL`.
- A `psPerT` of `null` must render "—" and never be marked best (and no highlight if all are null) → Task 3 `bestIndexes ignores nulls` + Task 5 test `shows a dash for a missing PS/t and does not mark it`.
- Cars with different version histories (963-24 only has 1.70–1.72) must share one date-ordered X axis with gaps, not interpolated lines → Task 6 test `breaks the line where a car has no point`.
