# UX & accessibility redesign — design

Date: 2026-10-16 · Branch: `feat/ux-a11y` · Scope: `site/` only (Python pipeline and data unchanged).

## Goal
Make GT7 BoP Radar easy to use for people of all ages (kids to older players, non-experts included).
The site's focus is **BoP**; leaderboard-based features (gtsh-rank) are on standby.

Success criteria:
- A first-time visitor can find their car and understand its latest BoP change without knowing any jargon.
- WCAG 2.1 AA: text contrast ≥ 4.5:1, touch targets ≥ 44×44 px, full keyboard use, works at 200 % zoom and at 375 px width.
- Lighthouse accessibility score ≥ 95 on Home, Car, Updates and Help.

Out of scope: gtsh-rank backfill, predictive model, agent, per-DR performance (separate sub-projects).

## 1. Structure
**Nav:** Home · BoP updates · Help (About becomes Help). Tracks is removed from the nav; `#/tracks` and
`#/track/...` routes are no longer linked anywhere (code kept, not deleted).

**Home (top to bottom):**
1. Big car search (56 px tall input, placeholder "Find your car…"). Live suggestions (name, maker, class) as a
   keyboard-navigable listbox (ARIA combobox pattern); choosing one opens `#/car/<id>`.
2. Latest BoP explained: "Version 1.71 · 20 Aug 2026". One card per class Gr.1–4 with a plain sentence
   ("13 cars got faster, 5 slower, 2 mixed") and the 3 most affected cars with the effect in words
   (e.g. "+6 PS, +15 kg → about the same"). "See all changes" button → `#/update/<v>`.
   "Most affected" = largest `|delta.pp|` in `data/updates/<v>.json` (already exported; no pipeline change).
3. Ranking per class: columns position, level, car, best track type, last change. PP and traits move to the
   car page. Below 700 px each row becomes a card. The "Which car for which track?" panel is removed.

**Car page:** large one-sentence summary first, then BoP history (chart + list), then technical details.
The "Leaderboard record" section is not rendered.

## 2. Readability & accessibility
- Base font 18 px; nothing below 15 px (chips, table headers, notes, footer); line-height 1.6; larger headings;
  mono numbers at text size. Use `rem` so browser zoom/font settings scale everything.
- Contrast ≥ 4.5:1 for all text in both themes (lighter muted grey on dark, darker on light).
- Meaning never by colour alone: verdicts read "▲ Faster", "▼ Slower", "◆ Mixed"; level letters keep the
  letter plus a name in the explanation ("S: among the best").
- Light/dark theme toggle in the header (default: system; choice remembered in `localStorage`, wrapped in try/catch).
- Interactive controls ≥ 44×44 px with spacing; strong visible focus outline (`:focus-visible`).
- Table rows become real `<a>` elements (keyboard + screen readers); "Skip to content" link; `aria-label`s on
  controls; language switch sets `<html lang>`.
- `prefers-reduced-motion`: no transitions.

## 3. Plain language & help
Term changes (EN / PT):
| Now | EN | PT |
|---|---|---|
| Buff / Nerf / Mixed | Faster / Slower / Mixed | Mais rápido / Mais lento / Misto |
| Fast / Medium / Twisty | Fast / Medium / Slow tracks | Pistas rápidas / médias / lentas |
| PP | Performance level (PP) | Nível de performance (PP) |
| Tier | Level | Nível |
| Traits | Strengths | Pontos fortes |

- First mention of BoP is explained inline.
- ⓘ buttons next to technical terms open a short explanation (popover; works with tap and keyboard, closes with Esc).
- Help page: "How to use" (3 steps), glossary (BoP, PP, PS/t, weight balance, track types, levels),
  "Where the data comes from" (GT ENG!NE), note that tyre wear/fuel are estimates.
- Empty search: "No car found for «xyz». Try just the maker, e.g. «Ferrari»."
- Data load failure: clear message + "Try again" button.
- EN and PT (Portugal) copy reviewed for the same tone.

## 4. Implementation
Split `site/app.js` (422 lines) into native ES modules, no build step:
- `site/js/i18n.js` — strings EN/PT + `t()`.
- `site/js/data.js` — loading JSON, error/retry.
- `site/js/ui.js` — shared components (verdict, level badge, info popover, search combobox, theme toggle).
- `site/js/pages/home.js`, `car.js`, `updates.js`, `help.js` (and existing `tracks.js` kept, unlinked).
- `site/js/main.js` — router.
`index.html` loads `js/main.js` with `type="module"`. `style.css` reworked with tokens for sizes/colours.

## Testing
- Chrome: desktop, 375 px mobile, 200 % zoom, keyboard-only walkthrough of Home → Car → Updates → Help.
- Lighthouse accessibility ≥ 95 on the four pages; contrast checked by a script over the CSS tokens.
- Existing Python tests still pass (untouched).
